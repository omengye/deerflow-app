## 真机与服务端联调

### 2.1.1 恢复专项（2026-10-28）

新增自动验收覆盖以下场景。网络切换的调度与持久化测试使用虚拟时间，字节限速测试使用真实本地 TCP、OkHttp WebSocket 和合成 v10 服务端；它们不等同于实体 Android 手机的无线网络与系统休眠测试。

| 场景 | 验证内容 |
| --- | --- |
| 已缓存的 1802 个事件 | 只请求保存位置之后的事件，没有新增内容时只需一个空事件页 |
| 10 万事件的长历史、每页延迟 20 秒 | 仅恢复末尾 100 个事件；允许总同步时间超过单页超时，仍持续前进 |
| 连续 24 次恢复中断 | 每轮重新从磁盘读取原子快照，最终 800 个文本片段完整且不重复 |
| 连续 30 次切网 | 取消旧恢复任务，仅最后一代连接能够完成 |
| 约 16 KiB/s、三次 WebSocket 帧中途断开 | 保留 1 万条已有消息，从 10 万事件游标继续恢复 512 个事件；不下载旧历史，不重复文本 |
| 无响应、无进度、旧回调、daemon epoch 变化 | 超时明确失败；不推进游标；旧回调不能提交；版本变化要求重新读取快照 |
| 待授权历史中断 | 控制历史进度独立保存，继续补读后仅保留当前授权和问题，不复活旧卡片 |
| 恢复过程中切换到同一会话 | 等待同一个恢复任务及其失败结果，避免误判已完成；不同会话的恢复互不占用该锁 |
| 无旧权限广播的增量恢复 | Full Access 必须取得新回执；丢失回执不自动再次发送，也不提交 prompt |
| 记忆回执和重复网络通知 | 相同配置及同一网络的重复通知不重连，主动刷新和实际切网仍生效 |

此版本继续使用 Waku v10，无需部署新的服务端协议。完整会话快照仍用于无缓存、主动刷新和重启核对；大于单页超时预算的异常响应会明确失败并保留进度。

| 系统时限 | 模拟 dataSync 超时 | 及时停止服务，无 ANR 或无限重启；服务器任务保留 |
| 通知权限 | 拒绝通知权限后使用 App，再从设置开启 | 前台功能正常；权限状态不会使连接循环重启 |

| 双端审批 | 手机和桌面看到同一审批，在一端处理 | 不自动批准、不自动重发；明确展示 v10 跨端完成通知的限制 |
| 审批断网 | 提交审批后立即断网 | 保留结果待核对状态，不能因重连自动重复提交 |
| 取消竞态 | 点击停止时任务恰好完成 | 不把断开/ACK当作取消完成，以最终执行事件为准 |
| 服务重启 | 流式途中重启 daemon | epoch变化触发重新读取；无法证实的执行结果保持待核对 |
| 切换服务器 | 在设置中切换地址或Token | 缓存与旧socket隔离，不把旧会话发给新服务器 |
| 附件弱网 | 上传途中断网 | 不能悄悄丢弃附件后发送文本；保留输入或明确报告未发送 |
| 存储故障 | 模拟磁盘不足/快照损坏 | 明确错误，不静默重置游标或丢弃未确认命令 |
| 认证/协议 | 错误Token或非v10服务端 | 停止自动重试，引导修正配置 |

## 服务端边界

本次 app 分支不改动 deerflow-api 工作区。当前服务端的请求去重缓存不是跨重启事务日志，事件重放是 runtime 生命周期内的日志，前台审批没有统一的 pending snapshot / resolved 广播。客户端以只读核对和显式待处理状态保护这些边界，不声称服务端具备尚未实现的保证。

旧 AG-UI 本地记录只读保留；旧执行检查点不会被当作新的 Go 会话恢复。
